# v0.5.1 配置管理验证

2026-11-10，按用户要求对照本机 SFM 配置管理并补齐 Windows 操作入口。

## 直接观察到的 SFM 行为

仪表配置卡片有添加、当前配置、编辑、刷新、共享。
编辑表单包含名称、远程类型、URL、自动更新开关、以分钟为单位的更新间隔、最后更新时间、查看内容。
点击配置名进入列表，列表编辑模式出现移除操作。对照时取消所有表单，没有更改 Mac 配置。

## Windows 实现

配置卡片置于仪表顶部，包含导入、编辑、更新、管理全部配置、查看内容、导出、删除。
管理列表可操作未启用的配置，并提供启用操作。
编辑远程 URL 和更新偏好；远程内容只读，本地 JSON 可保存；使用原生文件保存选择器导出 JSON。
单份更新间隔 1–525600 分钟，后台每分钟检查；旧配置继续继承原全局更新设置。
删除当前配置需要用户在应用内明确确认停服，后端拒绝直接删除仍在运行的配置。
删除内容保留在 profile-trash；编辑/更新前内容保留在 profile-history。应用尚未提供一键恢复入口，可重新导入备份内容。
配置内容修改前解析；更新后如果内核启动失败，恢复原文件、时间和运行状态；原系统代理开关保持。
配置编辑错误不再污染内核的运行错误字段。

## 验证结果

- Go 客户端测试：导入、内容读回、名称/URL/自动更新设置、无效 URL 和 JSON 拒绝、修改恢复副本、远程更新、真实内核重新加载、启动失败后恢复原工作配置、运行中删除保护、停服后删除与剩余配置选择。
- Windows 原生 Release/x64 构建通过。
- Windows 实例上用临时 inactive 配置完成 API 集成测试（scripts/test-windows-profiles.ps1）：元数据保存、loopback 模拟订阅下载更新、内容读回、无效 JSON 不覆盖原内容、删除与恢复副本；检查真实 active 配置名称、运行和代理状态保持。
- 原有托盘生命周期测试保留；此轮没有通过远程 GUI 逐个点击编辑/导出对话框。导出保存选择器和分钟级自动任务未做人工长期验收。

用户实际订阅、配置和认证数据未收入仓库。本轮保留 v0.5.0 安装备份于 Windows 的 %LOCALAPPDATA%/sing-box-win-backups/20261110-profile-management/app。
